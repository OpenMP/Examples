The \kcode{declare_reduction} directive can be used to specify 
user-defined reductions (UDR) for user data types.

In the following example, \kcode{declare_reduction} directives are used to define
\plc{min} and \plc{max} operations for the \ucode{point} data structure for computing
the rectangle that encloses a set of 2-D points.

Each \kcode{declare_reduction} directive defines new reduction identifiers,
\ucode{min} and \ucode{max}, to be used in a \kcode{reduction} clause. The next item in the
declaration list is the data type (\ucode{struct point}) used in the
reduction.
The \kcode{combiner} clause specifies the functions \ucode{minproc} and
\ucode{maxproc} to perform
the min and max operations, respectively, on the user data (of type \ucode{struct point}).
In the function argument list are two special OpenMP variable identifiers, \kcode{omp_in} and \kcode{omp_out},
that denote the two values to be combined in the ``real'' function;
the \kcode{omp_out} identifier indicates which one is to hold the result.

The initializer of the \kcode{declare_reduction} directive specifies
the initial value for the private variable of each implicit task.
The \kcode{omp_priv} identifier is used to denote the private variable.

The following example explains a few details of the user-defined reduction 
in Fortran through modules. The \kcode{declare_reduction} directive 
is declared in a module (\ucode{data_red}). 
The reduction-identifier \ucode{.add.} is a user-defined operator that
allows accessibility in the scope that performs the reduction
operation.
The user-defined operator \ucode{.add.} and the subroutine \ucode{dt_init} 
specified in the \kcode{initializer} clause are defined in the same subprogram.

The reduction operation (that is, the \kcode{reduction} clause) is in the main program.
The reduction identifier \ucode{.add.} is accessible by use association.
Since \ucode{.add.} is a user-defined operator, the explicit interface
should also be accessible by use association in the current
program unit.
Since the \kcode{declare_reduction} associated with this \kcode{reduction} clause
has the \kcode{initializer} clause, the subroutine specified on the clause
must be accessible in the current scoping unit.  In this case,
the subroutine \ucode{dt_init} is accessible by use association.

The following example uses user-defined reductions to declare a plus (\kcode{+}) 
reduction for a C++ class. As the \kcode{declare_reduction} directive 
is inside the context of the \ucode{V} class the expressions in the 
\kcode{declare_reduction} directive are resolved in the context of 
the class. Also, note that the \kcode{initializer} clause uses a copy 
constructor to initialize the private variables of the reduction and it uses 
as parameter to its original variable by using the special variable 
\kcode{omp_orig}.

A Fortran user-defined reduction that uses an array or array section requires 
an elemental procedure or one defined with scalar arguments for the combiner.
% The underlying OpenMP semantics require element by element processing 
% on the array elements. 
The following example illustrates this in
reductions A and B where \ucode{procA} uses scalar variables and \ucode{procB}
is an elemental procedure.

In reduction C the \ucode{procC} generic procedure is invoked for the 
user-defined reduction \ucode{addC}.
The interface \ucode{procC} has an elemental procedure, \ucode{proc_elem},
and an array procedure, \ucode{proc_array}.
When a generic procedure is used in a Fortran statement with an array, 
the Fortran standard requires that the array procedure be selected 
(\ucode{proc_array}). However, the user-defined reduction \ucode{addC}
selects an elemental procedure or a procedure with scalar arguments, i.e.,
\ucode{proc_elem} for the combiner.

\subsection{Non-commutative Reduction}
\label{subsec:noncommutative_reduction}
\index{reduction clause@\kcode{reduction} clause!noncommutative modifier@\kcode{noncommutative} modifier}
\index{noncommutative modifier@\kcode{noncommutative} modifier}
In general matrix-matrix multiplication is non-commutative.
In the following example matrix-matrix multiplications are calculated in 
a parallel worksharing loop with reduction.
To obtain correct results in the parallel reduction loop the
\kcode{noncommutative} modifier must be specified in the 
\kcode{reduction} clause. The implementation will maintain
the sequential order, and is free to perform partial, ordered reductions
and then combine the partial results in sequential order.
