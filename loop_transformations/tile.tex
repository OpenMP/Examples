In the following example a \kcode{tile} construct transforms two nested loops
within the \ucode{func1} function into four nested loops.
The tile sizes in the \kcode{sizes} clause are applied from outermost
to innermost loops (left-to-right). The effective tiling operation is illustrated in
the \ucode{func2} function. 
(For easier illustration, tile sizes for all examples in this section evenly 
divide the iteration counts so that there are no remainders.)

In the following C/C++ code the inner loop traverses columns
and the outer loop traverses the rows of a 100x128 (row x column) matrix.  
The \kcode{sizes(\ucode{5,16})} clause of the \kcode{tile} construct specifies
a 5x16 blocking, applied to the outer (row) and inner (column) loops.
The worksharing-loop construct before the \kcode{tile}
construct is applied after the transform.

In this example the \kcode{grid} modifier is used in the \kcode{sizes} clause
on a \kcode{tile} construct.  When the \kcode{grid} modifier is used,
the number of tiles in each direction is specified rather than the
tile size in each direction.
Here, with static scheduling and collapse of the outer iterations, the 4 tiles are
assigned to 4 different threads.

When the number of iterations (\ucode{n}) is not evenly divisible by the number of tiles (\ucode{s}),
then the number of iterations per tile is either $\lfloor n/s \rfloor$ or 
$\lceil n/s \rceil$ and which tiles have the additional iteration is implementation-defined.

Figure~\ref{fig:Example_tile_1} and Figure~\ref{fig:Example_tile_2}.
Figure~\ref{fig:Example_non_tile_3} shows the non-rectangular chunks that
can occur when worksharing the complete iteration space without tiling.
